传输 **`.bin`（二进制固件）** 是你作为嵌入式工程师经常会碰到的核心场景。对于 `.bin` 固件来说，它既不需要像 Markdown 那样渲染成富文本，也不需要像 PDF 那样在网页里看排版，它的核心诉求是：**二进制字节流的精准透传、一键复制/下载、或者直接向外暴露一个临时的烧录/升级拉取链接。**

针对 `.bin` 固件的特性，我们可以将它纳入这套轻量级阅后即焚系统的逻辑中：

### 1. `.bin` 固件在 Web 端的处理策略

| 场景 | 推荐交互方式 | 技术实现 |
| --- | --- | --- |
| **网页直传/烧录准备** | **Hex/ASCII 预览 + 一键复制/下载** | 小体积固件（或特定段）可以直接在网页用文本/Hex 视图看一眼（防呆校验），并提供一键下载或复制内存 Blob。 |
| **设备端 OTA 拉取（如 ESP32）** | **提供直链 / 阅后即焚 Token 链接** | 固件通常需要通过 HTTP/HTTPS 固件升级接口下载。你可以生成一个带有时效性（TTL）或单次拉取限制的临时直链（如 `GET /api/firmware/:token`），设备请求一次后立即销毁，防止固件被恶意长期外泄。 |

# TODO - 轻量级阅后即焚与快传分享工具（含 .bin 固件支持）

## Phase 1: 后端与存储架构设计 (Backend & Storage)
- [ ] **数据库与 TTL 设计**
  - [ ] 选型轻量级数据库（如 SQLite 或 Redis），支持设置过期时间（TTL）。

  - [ ] 实现 `POST /api/upload`：接收文本、文件、前端 Zip 包、以及 `.bin` 固件二进制流，生成唯一提取短链。
  - [ ] 实现 `GET /api/raw/:id`：获取文件流或文本内容，触发“访问次数递减”逻辑（读完/下载完即焚）。

  - [ ] 实现定时清理任务（Cron Job）：定期物理删除过期或次数耗尽的脏数据。

## Phase 2: 前端核心路由与解析渲染 (Frontend Core)
- [ ] **项目脚手架与路由**
  - [ ] 初始化轻量前端项目（如 Vite + Vue/React 或纯静态 HTML）。
  - [ ] 实现 `/s/:id` 动态解析路由，请求后端获取内容元数据。
- [ ] **Blob 动态渲染与二进制引擎**
  - [ ] **纯文本 (TXT/Code)**：使用 `<pre>` / `<textarea>` 承载，提供一键复制按钮 (`navigator.clipboard`)。

- [ ] **大文件 / ZIP 处理**
  - [ ] 限制单文件/包大小在 100MB 以内。
  - [ ] 针对非直显格式或超限文件，提供规范的 `.zip` 下载触发通道。

- [ ] **UI/UX 极简打磨**

  - [ ] 适配移动端响应式布局，确保手机浏览器上也能舒适查看。
